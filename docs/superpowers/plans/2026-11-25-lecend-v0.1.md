# lecend v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Claude Code plugin that captures short session labels (definition + latest status) into SQLite and shows them via `/lecend` and a side pane without sending anything to the main model.

**Architecture:** A Rust binary `lecend` owns all parsing, validation and storage (one SQLite file) and is driven as a JSON-in/JSON-out CLI. A thin TypeScript Claude Code mod under `plugin/` hooks `prompt.submit`/`turn.complete`, calls a cheap model through `$.model.complete`, shells out to the binary with `$.process.run`, answers `/lecend` display-only, and draws the pane.

**Tech Stack:** Rust 2021 (stable ≥ 1.80): `rusqlite` (feature `bundled`), `clap` (derive), `serde`/`serde_json`, `regex`, `anyhow`; dev: `assert_cmd`, `predicates`, `tempfile`. Mod: TypeScript/TSX against the `claude-code` module API (Claude Code ≥ 2.1.331), tests with `claude plugin test` (`claude-code/testing`).

**Spec:** `docs/superpowers/specs/2026-11-25-lecend-design.md` — read it first; this plan does not repeat its reasoning.

## Global Constraints

- Every `/lecend` answer is returned with `isTextDisplayOnly: true`; lecend never adds anything to the main model's context (no `prompt.compose`, no `context` entries).
- Capture never blocks a turn: `turn.complete` hooks only run `lecend turn` (local, ≤ 2 s timeout) and enqueue; everything else runs off the hook.
- Main loop only: `turn.complete` events with `agentId` set are ignored.
- Capture is on only when `session.start` has `isInteractive === true` (fail closed: false or missing → off).
- Every `/lecend` answer and the cost notice are never read by the model; the cost notice is a persistent display-only transcript row (mechanism verified in Task 1).
- The budget counts model calls attempted (bumped before each call), since failed calls cost tokens too.
- DB path: `${CLAUDE_PLUGIN_DATA}/lecend.db` (from `$.process.hookEnv()`); the mod has no `HOME`.
- Session id: `CLAUDE_CODE_SESSION_ID` / `$.session.id()`.
- Binary CLI: every subcommand except `version` takes `--db <path> --session <id>`; JSON on stdin where stated; success writes JSON (or text for `show`/`history`/`list` without `--json`) to stdout, exit 0; failure writes `{"error":"<message>"}` to stdout, exit 1.
- Limits: label ≤ 32 chars; definition ≤ 200 chars; status ≤ 200 chars; quote ≤ 300 chars; turn text sent to the model ≤ 12 000 chars (head 8 000 + tail 4 000); glossary entries sent to the model ≤ 12; known label names sent to the model ≤ 50 (most recently updated); default budget 200 model calls per session.
- Settings (`userConfig`): `model` (string, default `"haiku"`), `capture` (boolean, default `true`), `budgetPerSession` (number, default `200`), `stoplist` (string, comma-separated, default `""`).
- License Apache-2.0. Repo is public: no secrets, no personal data, no local paths of other projects.
- Commits: Conventional Commits, English, no AI attribution.

## Review Focus

1. **Binary not on PATH** → `/lecend` replies with install instructions; capture stays off: no per-turn process run, no model call, no error rows. Tests in Task 9 (install text) and Task 10 (no capture attempts).
2. **Model reply that is not clean JSON** (prose around it, ```json fences, truncated, several objects) → one JSON object is extracted if unambiguous, else the job is dropped and logged and `apply` is not called; glossary unchanged. Test in Task 10.
3. **Huge turn text** (100 KB answer) → only the model prompt is truncated (head 8 000 + tail 4 000); `scan`/`apply` receive the full text, so a quote from the tail still validates. Tests in Task 5 and Task 10.
4. **Two sessions writing the same DB at once** → WAL mode + `busy_timeout = 5000`; parallel `turn`/`apply` from two sessions both persist. Test in Task 5.
5. **Non-ASCII and multi-word labels** (`Karar 1`, `İ2`, `/lecend karar 1`, `/lecend edit Karar 1 = …`) → stored as written; label identity is case-insensitive (Unicode), so `w6` and `W6` are one label; multi-word arguments are one label. Tests in Tasks 5, 6, 9.

### Task 4: Label detection and `scan`

**Files:** Create `src/labels.rs`, `src/scan.rs`; Test `tests/cli_scan.rs`, unit tests in `labels.rs`; Create `tests/fixtures/w6.json`

### Task 5: `apply` — validate and store a model diff

**Files:** Create `src/apply.rs`; Modify `src/main.rs`; Test `tests/cli_apply.rs`

**Interfaces:**
- Consumes: `session::turn_index_of` (Task 3), `labels::Stoplist` (Task 4).
- Produces: `lecend apply` stdin `{turnId, prompt, answer, stoplist, diff:{new:[{label,definition,quote}], redefine:[…], status:[{label,status,quote}]}}` → `{"applied":N,"rejected":[{"op","label","reason"}]}`. Missing arrays mean empty. Unknown `turnId` → error.
- Rules exactly as spec §6.3. Reasons are fixed strings: `quote-not-in-turn`, `label-not-in-quote`, `label-not-in-turn`, `quote-does-not-state-meaning`, `too-long`, `stoplisted`, `ignored`, `already-defined`, `not-defined`, `pinned`, `user-edited`, `not-newer`, `same-definition` (no-op, not counted as rejection — omit from `rejected`), `already-applied` (whole call no-op when `turns.applied_at` is already set; returns `applied:0`, `rejected:[]`).
- Label identity: matched by `label_key` (Unicode lowercase); `new` for `w6` when `W6` exists → `already-defined`; `status` for `w6` updates `W6`.
- Quote match: exact substring of the full `prompt` or `answer` (never the truncated model text) after collapsing runs of whitespace to one space on both sides.
- Deterministic "quote states the meaning" check (spec §6.3, for `new` and `redefine`): the quote contains the label and at least one word of ≥ 4 letters from the proposed definition (case-insensitive, Unicode); otherwise `quote-does-not-state-meaning`. This is the mechanical floor; the prompt (Task 10) carries the rest of the rule.
- "Newer" compares the turn index with the label's latest definition/status turn index as it was before this call; all accepted ops commit in one transaction; `turns.applied_at` is set in the same transaction. A `status` for a label redefined in the same call attaches to the new version.
- Each rejection is also inserted into `rejections`.

### Task 8: `fork`

**Files:** Create `src/fork.rs`; Test `tests/cli_fork.rs`

**Interfaces:**
- `lecend fork --from <parent> [--at-turn N]` on `--session <child>`: one `IMMEDIATE` transaction; if `sessions.fork_done` is set for the child → `{"copied":0,"already":true}`. Otherwise copy parent's `terms`, `definitions`, `statuses`, `ignores` (rows with `turn_index ≤ N` when given; terms without any remaining definition are dropped), set child `forked_from`, `fork_turn`, `turn_base = max copied turn_index` (or N), `fork_done=1`. Returns `{"copied":rows,"already":false}`.
- `lecend fork --none` marks `fork_done=1`, `forked_from=NULL`, `fork_turn=-1` (no parent found) so `list` can explain (Task 6).
- `lecend lineage --transcript <path>` (no `--db`/`--session` needed) → `{"parent": <session id>|null, "sharedUserTurns": N}`: per `docs/notes/session-identity.md`, reads the transcript's `type:"user"` entries' `uuid`s, scans sibling `*.jsonl` files in the same folder (excluding itself) for the first user uuid; the parent id is that file's stem; `sharedUserTurns` = number of this transcript's user uuids also present in the parent file. Missing/unreadable transcript → `{"parent":null,"sharedUserTurns":0}`. Lines that are not JSON are skipped.

### Task 9: Mod — binary bridge, `/lecend` commands, pane

**Files:** Create `plugin/.claude-plugin/plugin.json`, `plugin/hooks/hooks.json`, `plugin/hooks/register.tsx`, `plugin/hooks/bin.ts`, `plugin/hooks/commands.ts`, `plugin/hooks/pane.tsx`, `plugin/types/index.d.ts`, `plugin/hooks/commands.test.tsx`

**Interfaces:**
- `bin.ts`: `runLecend($, args: string[], stdin?: unknown, timeoutMs = 5000): Promise<{ ok: true; json: any; text: string } | { ok: false; error: string; missing: boolean }>` — builds `--db ${CLAUDE_PLUGIN_DATA}/lecend.db --session <id>`; `missing: true` when the process cannot start (binary not on PATH). `checkBinary($): Promise<boolean>` runs `lecend version` once at `session.start` and caches the result for the module's life; when false, no other `runLecend` call is made except the install text path.
- `commands.ts`: `parseArgs(args: string): Command` where `Command` = `{kind:'list'} | {kind:'show',label} | {kind:'pane'} | {kind:'history',label} | {kind:'edit',label,field:'definition'|'status',text} | {kind:'pin'|'unpin'|'forget'|'unforget',label} | {kind:'off'|'on'}`. Syntax: `/lecend`, `/lecend <label>`, `/lecend pane`, `/lecend history <label>`, `/lecend edit <label> = <definition>`, `/lecend status <label> = <status>`, `/lecend pin|unpin|forget|unforget <label>`, `/lecend off|on`. Reserved first words are not labels; `/lecend show <word>` looks up a label named like a reserved word.
